# Designer 4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new designer flow, `designer4`, where sending an email beside the finished door is the price request and the lead, followed by a picture-led doorway step, a details step and a My designs page.

**Architecture:** Designer 4 is a subclass of Designer 3's app that swaps the handle behaviour, the ask and everything after it, without editing Designer 3's files. Its doors are rows in the existing `hd_enquiries` table (`kind` `enquiry`, `flow` `designer4`) with three new columns. Every lead event is written to a local queue and pushed to the manager app's API, so nothing is lost if the manager is unreachable.

**Tech Stack:** WordPress plugin, PHP (no framework), vanilla browser JS as UMD/IIFE modules, plain-Node tests (`node tests/js/<name>.test.js`), PHP tests (`php tests/php/run.php`).

**Spec:** `docs/superpowers/specs/2026-11-10-designer-4-design.md`. Mockups: `.superpowers/brainstorm/23829-1794304171/content/*.html`. Manager half: `../manager-app/docs/superpowers/plans/2026-11-10-website-leads-and-doors.md`, which must be live before this is released.

## Review Focus

- A door type with no "No Handle" choice, or no finger pull or bar handle (Stable has no pulls): the preview shows what exists and the door is never left in a state that can't be submitted (Task 8 test).
- Someone types another person's email: they must not see or change that person's older doors, and their details must not overwrite existing ones (Task 5 tests).
- The manager is down or the key is blank: the lead is still stored, both emails still go, and the event is delivered later exactly once (Task 3 tests).
- The same person submits twice in one visit (back, change, send again): one row is updated, not a second row or second email (Task 4 test).
- A reopened link to a removed door, or to a door whose deal is closed: My designs opens, and nothing can be changed (Task 5 tests).

## Shared contract with the manager

Events go to `POST {manager_url}/website-leads/events` with `Authorization: Bearer {manager_key}`:

```json
{ "eventId": "hd-123", "type": "door_added | door_changed | doorway_set | door_removed | details",
  "at": 1794300000000, "email": "nicola@example.com",
  "door": { "reference": "HD-2026-000090", "name": "Etna in French Navy", "summary": "Single Door · Etna · French Navy",
            "imageUrl": "…png", "designUrl": "…?design=TOKEN", "choices": [{ "heading": "Door Design", "label": "Etna" }],
            "frame": null, "sideGlass": "" },
  "details": { "name": "", "phone": "", "postcode": "", "overwrite": false } }
```

`200 {ok, dealId, status}` is delivered. `409` with code `deal_closed`, and `422`, are final (never retried). Anything else is retried. Status is read from `POST {manager_url}/website-leads/status` `{references: [...]}` → `{doors: [{reference, status: "pending"|"estimate_sent"|"closed"}]}`.
